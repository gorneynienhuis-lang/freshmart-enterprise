## 当前业务范围

- 真实注册、登录、令牌轮换、注销；员工与会员显式分权，没有万能管理员。
- 商品分类、搜索、详情、购物车；服务器计算商品价格、整数分金额、会员价/临期价和新人券。
- 地址与配送窗口、短期报价、创建订单。报价不占库存；下单事务同时占用券、配送名额和合格批次库存，任一步失败全部回滚。
- 订单支付沙箱：服务端生成金额、验证回调签名、渠道事件去重、订单资金只入账一次；重复或晚到的实收原路退款，不恢复失效订单。
- 拣货人员领取任务，按已分配批次提交实际件数/克数；称重超估重10%拒绝。少了退差，多了另行补款，差额未结清不得发货。
- 拣货人员交接给有效配送员，配送员仅处理自己的任务；会员可查看签收码，配送员提交码完成签收，失败次数受限。
- 未发货订单取消、未支付/补款超时自动关闭、释放占用；已实际出库的货物须登记回库和质检，不能凭取消退款直接恢复可售库存。
- 已完成7天内的 SHORTAGE/LATE 售后：会员申请、客服领取审核、另一名财务执行原支付单退款；成功渠道回执后才记账完成。人工退款不会跳过财务执行授权。
- 运营/财务看板从真实数据聚合；客服订单查询在数据库限定本人关联工单，财务不获取配送地区与详细地址。

## 一条可操作的业务路径

1. 用会员登录或新注册，加入商品到购物车，新增松江区/长宁区服务地址，选择可用配送窗口并报价、提交订单、沙箱付款。
2. 切换拣货账号到员工工作台，领取刚创建的订单，提交实拣量。例如估重500克实际450克会产生退差；待自动退款成功再交接。
3. 切换配送账号查看自己的配送任务。会员订单中取签收码，配送员凭码完成；其他会员或配送员不能越权读取/操作。
4. 会员在完成订单中申请缺货/延误售后。客服领取并审核金额，财务账号执行退款，刷新查看真实状态。

登录、购物车、订单与员工操作中补充的工程表单用于联调，不作为最终视觉稿。未完成能力不会用假数据或假成功提示代替。

## 契约与实现边界

统一合同已更新至 **v0.1.1**：`quantity`始终按基础单位传递，PIECE为件、GRAM为估重克数；前端“份”的加购步长转换成克后请求，不再乘第二次份重。财务看板未授权的经营数量返回`null`，财务订单联系方式省略地区，不能用0伪装无权限数据。

OpenAPI共有91项操作，其中58项有Demo控制器路由。这个数字是代码覆盖，不能解释为58项所有业务分支均验收。`x-demo-limitations`注明部分能力；自动生成的前端类型与清单来自同一份合同。

当前未完成：退款worker的有限重试/人工处理队列（目前对异常保留原业务号并延迟重试；不能声称已验证完整外部渠道故障恢复）、品质售后所需的私有图片上传与证据授权（QUALITY/非空evidenceMediaIds明确拒绝）、评价提交及持久化（查询只返回空列表）、批次/商品运营编辑、库存盘点与重分配、配送异常恢复、员工管理、对账报告、完整监控面板、生产部署/备份恢复。Redis尚未接入，当前库存与资金一致性依赖数据库事务、行锁和唯一约束。

尚未进行生产环境验收、长时间压力测试或真实第三方支付对接。本机并发守恒检查不等于生产QPS或可用率承诺。
