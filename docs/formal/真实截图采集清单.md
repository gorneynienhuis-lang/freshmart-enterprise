## 六、拍摄规则

1. 真实系统截图优先使用公网版本；本机截图必须在图片说明中标注 `localhost` 和运行端口。
2. 浏览器截图保留地址栏和关键页面上下文；命令行截图保留命令和结果，但不要出现密码、Key、Cookie、Token或私有签名。
3. 每张截图只表达一个结论，避免把多个窗口缩得过小；建议PNG格式，宽度不低于1440像素，移动端按390像素单独截取。
4. 失败、未执行和用户暂缓都必须如实保留。没有真实压测结果时，不要用脚本截图替代QPS、RT和错误率。
5. 文件命名使用编号加短名，例如 `UI-01-public-home-1440.png`、`AUTH-10-forbidden-403.png`、`OPS-05-prometheus-firing.png`。

## 七、逐张操作说明（按这个顺序拍）

下面的“公网首页”统一指：`https://freshmart-enterprise-production.up.railway.app/`。如果公网暂时打不开，就在本机先运行 `./scripts/demo-start.sh`，改用 `http://localhost:5173`，并在图片说明中标注 localhost。登录时使用对应角色的现有演示账号；账号可以通过项目负责人私下提供的凭据取得，密码不要写进截图或报告。

### A. 用户端主流程

- **UI-01**：打开公网首页，等待商品图片和东小锦加载完成；确认没有登录弹窗、错误提示或破图。浏览器缩放保持 100%，截取从地址栏到首页主视觉、分类、商品卡和东小锦的完整画面。
- **UI-02**：点击顶部搜索框，输入“番茄”，点击“搜索”；地址应进入 `/#/products?keyword=番茄` 或等价结果页。截取搜索词、筛选/排序、商品图片、价格和分页，不要只截一张商品卡。
- **UI-03**：在 UI-02 的结果中点击任意商品卡进入详情页；确认详情中有商品名、规格、SKU、会员价、按件/称重说明和“加入购物车”。截取详情主体和地址栏，避免截到账号密码。
- **UI-04**：在详情页加入商品，打开购物车并点击“去结算”；登录会员、选择收货地址、配送日期/时段和可用优惠券，等待服务端报价出现。截取商品行、地址、时段、优惠、运费和应付金额。
- **UI-05**：在结算页点击“提交订单并支付”，在“沙箱支付确认”窗口点击“模拟支付成功”。截取订单号、沙箱提示和成功结果；不要出现真实支付平台或银行卡信息。
- **UI-06**：点击“我的订单”或进入 `/#/orders`；找到刚才的订单，截取订单状态、配送时段、订单金额、商品行、称重说明/签收码和时间线。若订单数据尚未完成，不要把未完成状态写成已完成。
- **UI-07**：点击右下角东小锦，选择“怎么下单？”或输入同样的问题；等待回复出现“在线”和真实模型回答后再截图。画面应同时包含问答面板、回答来源/状态和东小锦，不要截到 API Key。
- **UI-08**：分别在首页等待或悬停东小锦，记录拎菜袋、挥手、记录板、菜篮四个实际状态；每个状态单独截图，或用一张四宫格拼图但必须来自真实渲染。不能用概念图替代运行时截图。

### B. 角色、登录与越权

- **AUTH-01**：退出登录或使用无痕窗口打开公网首页；保持“你好，请登录”状态，截取仍可浏览分类、搜索和公开商品的画面。
- **AUTH-02**：未登录时直接打开 `/#/orders`，或在开发者工具 Network 中刷新受保护的订单请求；截取页面的“需要登录”提示，若截 Network 则只保留请求路径和 HTTP 401，隐藏 Cookie/Authorization。
- **AUTH-03**：通过顶部“你好，请登录”登录 MEMBER 账号，进入 `/#/orders` 或会员中心；截取“我的订单、地址、继续选购”等会员入口，不要展示手机号全量或密码。
- **AUTH-04**：用 OPERATOR 账号登录，点击“工作台”进入 `/#/operations`；截取商品/SKU、经营概览、规则或容量等运营可见模块，确保页面顶部能看到当前岗位。
- **AUTH-05**：用 PICKER 账号登录同一 `/#/operations`；滚动到“拣货任务”，截取批次、计划数量、领取/录入实拣按钮和当前身份。不要把会员私人地址或原始售后理由带入画面。
- **AUTH-06**：用 COURIER 账号登录 `/#/operations`；滚动到“配送任务”，截取待交接/配送中任务、交接或确认签收入口和岗位标识。签收码只在演示需要时显示，其他个人字段打码。
- **AUTH-07**：用 SERVICE 账号登录 `/#/operations`；滚动到“售后工单”，截取领取售后、查看品质证据或审核入口。若没有可用工单，截取空状态，并在文件说明中注明“真实暂无工单”，不要伪造。
- **AUTH-08**：用 FINANCE 账号登录 `/#/operations`；滚动到“退款执行”或“对账”区域，截取退款状态、金额和执行/重试入口。会员姓名、电话、备注和凭据必须打码。
- **AUTH-09**：用 ADMIN 账号登录 `/#/operations`；截取“员工与权限”、角色、账户状态、首次改密和审计入口。不要点击停用或改角色，只拍只读画面即可。
- **AUTH-10**：先用低权限 MEMBER 或 COURIER 登录，再尝试打开 `/#/operations` 中不属于该角色的功能，或访问管理员接口；截取明确的 403/无权限提示和当前角色。不要把前端隐藏按钮当成唯一证据，最好同时保留 Network 中的 403 状态。
- **AUTH-11**：准备两个不同会员账号。会员 A 创建或已有订单后退出，会员 B 进入 `/#/orders`，应看不到 A 的订单；如需证明资源请求，使用 Network 查看 A 订单 ID 返回 404。私有品质图片必须展示未授权拒绝、授权客服可读两种结果，所有账号信息打码。

### C. 工程、架构和安全

- **ENG-01**：浏览器打开 GitHub 私有仓库主页，显示仓库名、`main` 分支、最近提交和仓库说明；截取地址栏和提交信息，隐藏个人邮箱等不必要信息。
- **ENG-02**：在仓库主页点击“Commits”，截取真实提交历史，至少能看到功能开发、测试修复、部署修复或文档提交。不要用本地手写列表替代 GitHub 提交历史。
- **ENG-03**：在 VS Code、Finder 或 GitHub Code 页面展开项目根目录，截取 `backend`、`frontend`、`database`、`deploy`、`contracts`、`scripts`、`tests` 的目录结构。
- **ENG-04**：打开 `contracts/openapi.yaml`，或打开生成的接口文档；截取一组公开 GET、一组需要角色的接口和统一响应结构，避免把完整 Token 或测试密钥带入画面。
- **ENG-05**：在编辑器打开 `database/migrations/V001__identity_catalog.sql` 到 `V013__refund_recovery.sql` 的文件列表，或在数据库工具中展示实际表结构和 ER 关系。截图中不能出现数据库连接密码。
- **ENG-06**：打开 `backend/src/main/java/com/freshmart/identity/TokenCodec.java`、`SecurityFilter.java` 或对应安全测试，截取密码哈希、会话吊销、限流或权限校验代码；只拍代码逻辑，不拍运行时密钥。
- **ENG-07**：使用已有的真实退款/支付幂等演练结果，截取第一次请求成功、重复请求返回相同结果、最终只有一笔退款的终端或报告。没有真实演练结果时，只截幂等测试代码，不能把示例 JSON 当成实测。
- **ENG-08**：库存并发批量测试目前是用户暂缓项目。只能截 `scripts/e2e-concurrency.mjs`、测试状态中的 `USER_DEFERRED` 或单次库存不足拒绝；禁止把脚本内容截图冒充 QPS、RT 或并发通过结果。
- **ENG-09**：在浏览器分别打开一张商品公图和一张私有品质图；公图应正常显示，未授权私图应返回拒绝/404，授权客服会话才可读取。截取地址栏和结果，隐藏签名参数。

### D. 缓存、监控、异常和恢复

- **OPS-01**：先确认本机隔离 Redis 已启动，再在终端运行 `python3 scripts/redis-runtime.py probe --instance .runtime/redis-cache`，截取第一次分类查询的 miss/加载证据。终端中不要显示环境文件内容。
- **OPS-02**：不清理 Redis，重复打开首页或分类，再运行同一个 probe/status；截取第二次查询的 hit、命中计数或缓存状态，必须能与 OPS-01 区分。
- **OPS-03**：仅对项目自己创建的 Redis 实例执行 `python3 scripts/redis-runtime.py stop --instance .runtime/redis-cache`，刷新首页/分类证明仍可读取；随后立即重新启动。截图需要同时保留“Redis 不可用”和页面仍可运行的证据，不能停止不明服务。
- **OPS-04**：打开本机 Prometheus `http://127.0.0.1:9090` 的 Targets 页面，或使用项目监控脚本的 `targets` 操作；截取 fresh-mall 目标 `UP=1`、抓取时间和至少一个低基数业务指标。
- **OPS-05**：使用项目已有的真实故障演练，在 Prometheus Alerts 页面截取目标 DOWN 或退款失败告警处于 FIRING；规则测试 fixture 只能证明规则语法，不能冒充真实应用告警。
