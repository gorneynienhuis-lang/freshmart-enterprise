# 企业级生鲜商城需求文档 · 第一版源稿

版本0.1.0，2026-10-18。作者Codex。用途：需求评审与实现输入。实现状态：未实现/待验证；正式Word版在流程与契约冻结后编排。品牌及全部视觉以用户确认结果为准。

## 1 目标与业务边界

面向单自营门店、单仓的生鲜零售，建立浏览→购物车→报价→预约下单→沙箱付款→FEFO拣货与称重→退差/补款→配送→签收→售后→退款对账的闭环。通过并发库存、批次追溯、幂等支付、细粒度权限、可观测性和一键部署展示企业级工程能力。

本版不接真实支付账户，不产生真实扣费；不做多商户、多仓拆单、骑手路径优化、付费会员、秒杀与分布式微服务。免费会员、新人券、临期专区和预约配送为首期范围。演示账户与订单必须为合成数据。

## 3 参与者与用例

| 参与者 | 主要目标 | 数据边界 |
|---|---|---|
| 游客 | 浏览、检索、了解价格和配送 | 公开商品数据 |
| MEMBER | 管理地址/购物车、付款、订单、售后和评价 | 本人资源 |
| OPERATOR | 商品/价格/时段/营销维护 | 所属门店 |
| PICKER | 批次入库、拣货、称重、损耗与质检回库 | 所属仓库与任务 |
| COURIER | 接收配送任务并确认送达 | 分配给自己的订单 |
| SERVICE | 审核售后与处理异常 | 所属门店、脱敏必要信息 |
| FINANCE | 退款执行、资金对账、差错处理 | 财务数据，不含不必要住址 |
| ADMIN | 账号、员工角色配置和审计 | 不自动继承业务动作权限 |

完整动作矩阵见contracts/permissions。员工可同时显式拥有MEMBER，但采购个人订单使用自己的顾客上下文，不能用后台权限访问他人订单。

## 4 功能需求与验收入口

| 编号 | 功能需求 | 最小可验证结果 |
|---|---|---|
| FR-01 | 注册、登录、刷新、退出与禁用 | token过期/注销后访问失败；角色不可由客户端伪造 |
| FR-02 | 分类、搜索、商品详情、临期展示 | 售罄可见不可买；过期批次不可分配；公开响应无库存台账 |
| FR-03 | 购物车与本人地址 | 数量边界校验；换他人ID得到404 |
| FR-04 | 配送时段及报价 | 报价包含优惠/运费/称重说明/到期；满额时段不可选 |
| FR-05 | 创建订单 | 库存、券、名额、订单原子提交；失败不残留锁定 |
| FR-06 | 支付与超时关闭 | 回调重复不重复入账；关单后成功自动退款，不恢复订单 |
| FR-07 | FEFO与批次追踪 | 同SKU可跨多批次，选择到期早且覆盖送达时间的可售库存 |
| FR-08 | 拣货称重及差额 | 每500克价格正确折算；少退差、多另补；补款未成拒发货 |
| FR-09 | 配送签收 | 仅分配配送员可更新；签收状态不可任意倒退 |
| FR-10 | 取消与回库 | 未拣释放预占；已拣需质检回库，资金退款独立可重试 |
| FR-11 | 售后/证据上传/评价 | 7天窗口、每行金额限额；品质退款不恢复可售量 |
| FR-12 | 财务退款与对账 | 人工售后审核人不可执行同笔退款；流水可追溯不重复支付 |
| FR-13 | 商品/价格/库存管理 | 版本冲突可见；调整理由与前后值审计 |
| FR-14 | 观测与部署 | Compose复现、种子/账号说明、健康检查、traceId可定位异常 |

## 5 关键业务流程

正常：报价→创建PENDING_PAY（库存/时段/券预占）→支付SUCCESS与订单PAID→PICKING→称重确认并库存出库→READY_TO_SHIP→必要补款SETTLED→DELIVERING→FINISHED。退款处理与履约状态分开。

异常：库存不足/时段约满→整笔下单回滚；支付15分钟超时→CLOSED并释放；晚付→退款任务；称重补款到期未付→CANCELED并退款，已拣实物独立质检回库；品质投诉→审核→财务退款→完成，库存不复活。详尽转移见state-models，公式见business-rules。

## 6 数据、非功能与交付

数据实体至少含用户/角色/权限、地址、SPU/SKU、库存批次/台账/分配、时段容量、报价与快照、订单/行、支付、差额、退款、配送任务、售后、评价、券、outbox、审计。ER及约束在设计文档说明。

非功能指标必须附环境、负载、时长、错误率和证据。安全以资源级授权、参数白名单、密码哈希、会话吊销、上传校验、审计脱敏为基础；一致性以MySQL事务和唯一约束为基础；可靠性以outbox恢复、对账、备份恢复与回滚演练为基础。具体场景与性能初始目标见acceptance-baseline，不沿用“1000QPS/99.9%”为已达成事实。

最终交付：源码+数据库脚本+部署脚本的压缩包，企业级需求/设计/测试报告三份文档，一份PPT，一段不超过15分钟的真实运行录屏。视频必须包含业务闭环、角色权限拦截、异常流程、企业级能力与监控/压测、架构、难点、AI使用复现、测试部署与总结，不能仅播放PPT。
