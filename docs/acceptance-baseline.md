## 2. 执行记录与证据结构

每次运行以 `runId = 日期时间-commit短码-环境` 建立 `evidence/<runId>/`，保存以下资料。可使用其他实现工具，但证据内容不能省略。

| 路径 | 必须记录的内容 |
|---|---|
| `manifest.json` | commit、OpenAPI 版本和哈希、环境、执行人、开始结束时间/时区、机器与容器资源、数据库/缓存/队列版本、配置快照、测试数据生成种子 |
| `cases.csv` | caseId、实际输入/参数、expected、actual、PASS/FAIL/BLOCKED/SKIPPED/NOT_RUN、证据相对路径、缺陷号、重试关联；本文件未执行项目初值为 NOT_RUN |
| `api/` | 脱敏 HTTP 请求/响应、真实状态码、traceId、调用时间、operationId |
| `db/` | 关键事务前后快照/只读查询结果、库存流水、资金流水和唯一约束检查；不能只保存最终截图 |
| `tests/` | 测试命令、原始标准输出、JUnit/等效机器可读结果、覆盖率报告、E2E 录屏/截图 |
| `load/` | 压测脚本、负载参数、JTL/等效原始样本、聚合报告、服务端资源和错误日志 |
| `ops/` | 启动/健康检查/停启/备份恢复/回滚命令与日志、告警及监控截图 |
| `video/` | 演示脚本、真实录屏时间点与 caseId 映射、媒体时长检测结果 |

录屏、截图和原始日志须脱敏；不得录入真实用户账号、手机号、详细住址、密码、JWT 或密钥。保存的是测试账户与合成数据，敏感凭证使用占位引用。截图或浏览器 mock 只证明对应界面，不证明真实资金、库存和授权结果。

## 3. 固定测试夹具

- 用隔离数据库生成两名会员 `M1/M2`，仓储 `W1/W2`，配送 `D1/D2`，运营 `O1`，客服 `S1/S2`，财务 `F1/F2`，管理员 `A1/A2`；另设 `SF1` 显式兼 `SERVICE+FINANCE`，`AM1` 显式兼 `ADMIN+MEMBER`。默认员工不具备 MEMBER。
- 使用可控业务时钟；正常批次、临期批次、已过期批次、到期早于配送窗结束的批次、隔离批次、可跨批次分配商品各一组。基于运行日生成日期，固定 seed，并记录实际时间，不直接导入旧表硬编码库存。
- 计件最后 1 件商品；可售库存足够且容量为 30 的未来配送时段；另备预约已截止时段；正常和称重 SKU。金额用整数分、重量整数克，不使用二进制浮点作账。
- 支付只接沙箱。测试回调由受控沙箱签名工具生成，区分成功、失败、重复、乱序、晚到、错误金额/币种/签名和未知渠道结果。真实支付和真实扣款不在验收范围。
- 每个案例独立重置或显式声明前置依赖。并发测试开始前证明初始库存/容量/流水清零，结束后按守恒关系验证，而非只数 HTTP 成功响应。

## 7. 性能与可靠性参数化验收

以下是首次校准用的候选值，不是已达到的指标。实施者先记录环境并完成基准测量，再以 ADR 固定课程演示目标；不得临时降低阈值掩盖失败。500 在线不是 500 并发请求，也不能直接推导 1000 QPS。

| 参数 | 可配置初值 | 必须报告的口径 |
|---|---|---|
| 应用资源 | 2 vCPU、4 GiB；具体宿主硬件待填 | CPU 型号、系统/架构、CPU quota、内存限制、JVM heap；压测端独立资源 |
| 数据库/Redis 资源 | 数据库 2 vCPU/4 GiB，Redis 1 vCPU/1 GiB，是否独占待填 | 版本、连接池、索引、持久化、网络与磁盘；不能把不同硬件结果直接对比 |
| 数据量 | 1000 SKU、10000 批次、10000 会员、100000 历史订单 | seed、索引/统计信息、有效/过期/隔离比例；压测订单与库存足够且可复位 |
| 预热/稳态/重复 | 预热 120 秒，稳态 600 秒，3 次 | 保留每次原始数据；冷缓存与热缓存分别报告，不择优只报最好一次 |
| 混合负载 | 浏览 70%、购物车/报价 20%、下单/支付/查询 10% | 每个业务链脚本、思考时间、到达率、并发上限、成功/失败定义；下单与沙箱回调拆开测 |
| 起始吞吐 | 总到达率 100 req/s，并发上限 100 | 先测此值再阶梯升压；不得称为正式业务容量；1000 QPS 仅作另立场景的压力探索目标 |
| 延迟与错误 | 读接口 P95≤500ms/P99≤1000ms；写接口 P95≤1000ms/P99≤2000ms；非预期错误率≤1% | 分 operation；均值同时可报但不代替尾延迟；预期库存不足/容量拒绝单列，全部响应仍纳入原始分母 |
| 缓存命中 | 热缓存读场景候选≥80% | key 集合、TTL、预热方式和分母；不得用“命中”掩盖过时价格/可售错误 |
| 最终一致性 | 正常依赖下业务事件 60 秒内收敛；故障恢复后 120 秒内收敛 | 从本地提交到资金/库存/订单一致的时差；失败/死信/重试明细全保留 |
| 健康与告警 | 探测每 10 秒、连续 3 次失败触发，60 秒内产生告警事件 | 监控真实采集、触发时间、恢复时间；告警是否实际送达与仅生成分开记录 |
| 备份恢复候选 | RPO≤24 小时、RTO≤30 分钟 | 真实备份时间、恢复数据点、恢复全流程时间及关键账核对；须在隔离环境实测 |
| 单测覆盖率候选 | 业务代码行覆盖≥60% | 工具/版本与排除项；另核关键事务/金额/状态/权限分支，不用覆盖率替代正确性 |
| 可用率目标 | 99.9%，统计窗 30 天 | SLI 的成功请求或探测时间口径、计划维护与故障分母；运行不足统计窗仅报告实测样本，不宣称已证明长期 SLA |

压测通过需同时满足业务守恒、延迟、错误率和资源条件。出现库存为负、重复收退款、越权、不可恢复数据损坏时直接失败，不能用高 QPS 抵消。性能数据为空时，正式测试报告保留“未执行”，不填写推测数值。
