# 登录与后台使用

2026-10-18。当前采用用户选定的 R03 主要页面，分类与移动端已修正；R04 作为可回看的备选保留。支付为课程沙箱，不发生真实扣款。下面的地址为本机入口，公网地址尚未生成。

## 从哪里打开

- 商城：<http://localhost:5173/>
- 员工与管理入口：<http://localhost:5173/#/admin>，也可点击页面右上角「工作台」。
- 会员订单：<http://localhost:5173/#/orders>
- 会员收货地址：<http://localhost:5173/#/addresses>，也可从账户导航、订单页或结算页「管理地址」进入。
- 密码修改：登录后点击「修改密码」，或访问 <http://localhost:5173/#/account/password>。

会员与员工使用同一个登录框。不同账号登录后，服务器决定可访问的功能；更改网址不能绕过权限。员工登录后自动进入工作台。管理员账号不是所有岗位的万能账号。

这些号码不发送短信，也不联系实际手机号。本机初始演示密码在项目的 **`.runtime/demo-accounts.txt`**，可以直接打开该文件，或执行 `./scripts/demo-credentials.sh` 查看。该文件权限 0600、被 Git 忽略；不要把密码放入提交、公开截图或录屏。本机旧演示账号使用同一初始演示密码；本人修改后应使用新密码，原文件不会自动更新。

公网部署会重新生成七个**互不相同的随机初始密码**，与本机完全独立，全部要求首次登录改密。公网密码清单在部署机器的 `deploy/private/accounts.txt`，通过 `python3 scripts/deploy-public.py credentials` 私下查看；目前尚未为真实公网域名生成这份清单。部署完成后再交付最终网址与对应密码，不把离线测试域名当成已上线地址。

## 如何查看后台

1. 用 `13800000007` 和本机私有密码登录。工作台的「员工与权限」显示真实员工、脱敏手机号、角色、状态、是否完成首改及版本；每页 20 人。
2. 「新增员工」填写名称、手机号、至少 12 位的临时密码并分配岗位。创建后的响应不回传密码；请把临时密码单独安全交给该员工。初登必须先改密，改密成功后重新登录才能操作业务。
3. 「调整角色」或「停用/启用」均须填写原因。服务端检查版本并保存审计；角色变更或停用立即吊销该员工的旧会话。当前管理员不能修改自己的角色或状态，系统必须保留至少一名有效管理员。
4. 想看经营数据，退出/切换为运营 `13800000006`。选择日期后点击「查询」；支付、退款按所选业务日统计，库存与待拣任务为当前值。财务账号的三项经营库存数据显示「未授权」，不把它们错误地显示为 0。
5. 拣货、配送、售后及退款分别使用对应岗位账号。用户订单页提供签收码；管理员不能代替配送员确认签收，也不能跳过客服与财务分工直接退款。

老师可自行注册会员体验购物。验收员工权限时按需要另建临时岗位账号，演示后停用；主管理员密码仅由项目负责人持有。账号密码遗失后的管理员重置流程尚未提供，勿声称页面已有「忘记密码」或密码找回能力。

## 当前范围与下一步

已接入上述真实业务和员工治理，以及下列v0.2增量。最新剩余范围见 [后续工程范围](待补齐工程范围-v0.2.md)，早期工程差距文件保留历史状态，不能用早期列表推断当前实现，也不能把已有接口当作全项目已验收。

推荐上线方式与费用边界见 [公网部署](../deploy/公网部署.md)。部署完成还要从外网实际验收登录、权限、业务闭环、数据持久化和恢复，再提供可分享的网址。


v0.2.0 真实工作入口：

- OPERATOR 工作台新增商品草稿、SKU与改价、公开商品图上传、上下架、配送时段及经营规则。新草稿没有SKU时显示“未配置规格”；完成有效规格后方可上架。
- PICKER 工作台新增批次入库（真实生产/到期时间）、盘点调整、隔离/恢复/报废、只读流水及领单后的FEFO显式重配。历史未记录生产日期显示“未记录”。
- COURIER 对本人配送中的任务可以按目的和原因临时查看联系信息、报告异常；关闭窗口或离开页面清空私密显示。SERVICE 只处理指派给自己的配送异常，可恢复给原配送员。
- MEMBER 完成签收后可对实际收到的订单行评价一次，可选择上传评价图并明确授权公开；品质售后须提供本人该订单图片。SERVICE 领取后才可查看品质证据，FINANCE由不同账号执行审核后的退款。
- FINANCE 工作台可按上海业务日生成对账快照，查看内部账目与独立沙箱凭证差异；报告不会改账或再次退款。历史缺少凭证也会明确显示。
- ADMIN 新增审计查询，默认最近7天、时间窗最多31天；只显示脱敏原因和事件时角色。历史没有记录的结果显示“历史未知”，不虚构追溯数据。

新增后台呈现沿用R03红白风格，未替用户声称已逐页批准。密码仍只在上文私有文件；不要把管理员密码、私有图片或未脱敏录屏分享给普通访客。

v0.2.1 新增入口：

- 会员地址可编辑、设默认和确认删除；保存后结算会重新读取地址并生成新报价，旧订单保留原地址快照。发生版本冲突时刷新列表，不覆盖其他窗口的新内容。
- 商品、订单、售后和旧员工队列均由服务器每页20条返回，可前后翻页或跳页；页码与状态筛选可在刷新后恢复。后台订单支持完整订单号精确查询，搜索内容仅保留在当前页面内存。
- 会员在发货前可自行取消，或明确提交「请求客服协助取消」。申请仅分派独立客服，不冻结履约；无可用客服则申请失败且订单不变。受派客服在「订单查询」中操作，不能查询无关订单；成功发货或订单取消会自动结束协助。
- 会员可撤回尚未审核的售后；原拣货员在已取消的本人任务中登记实际合格/隔离回库数量。取消或退款本身不会增加可售库存。
- 财务仅对真实FAILED且已由独立执行人受理的原退款显示重试入口，复用原退款业务号；SUCCESS不能再次重试。渠道真实失败到FAILED的完整故障演练尚未完成，不能把该按钮已有当作故障治理已验收。
