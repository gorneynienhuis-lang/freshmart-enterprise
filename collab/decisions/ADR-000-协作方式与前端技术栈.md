# ADR-000 · 协作方式与前端技术栈

- 日期：2026-10-18
- 状态：✅ 已定（组长确认）

## 背景

队友（成员A/B/C）交付的只有需求与设计前段，没有代码；三份文件之间术语和规则互相矛盾。组长决定由两个 AI 分工完成实现：ChatGPT 负责后端，Claude 负责前端与全部视觉（含重做品牌与页面布局）。两个 AI 无法直接对话。

## 决定

1. **合同优先**：`contracts/`（glossary、conventions、openapi.yaml）是前后端唯一事实来源。
2. **目录所有权**：后端只写 `backend/`，前端只写 `frontend/`、`design/`，合同按 README 的流程改。
3. **异步交接**：`collab/HANDOFF.md` 交接日志 + `collab/requests.md` 申请单，组长负责转达"去读 HANDOFF 继续"。
4. **前端技术栈**：React + Vite + TypeScript，开发期 MSW 按合同 mock。
5. **版本管理**：私有 GitHub 仓库，`be/*`、`fe/*`、`contract/*` 分支。
6. **AI 使用记录**：两个 AI 每次收工按七要素写 `collab/ai-log/`。

## 备选方案

- 前端用 Vue 3：贴合第九章 RuoYi-Vue，老师更熟；未采用，组长偏好 React。
- 不做版本管理、只靠共享文件夹：最简单，但同时编辑会互相覆盖、改坏无法回退；未采用。

## 风险

- 合同漂移：后端实现与 `openapi.yaml` 不一致 → 用代码生成文档并在 CI 里对比。
- 若后端选 RuoYi，其默认返回结构与约定不同 → 在 ADR-001 中处理。
- 两边同时改 `glossary.md` → 规则改动必须经组长确认并记入 decisions。
