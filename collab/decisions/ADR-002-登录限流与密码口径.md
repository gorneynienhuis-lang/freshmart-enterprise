# ADR-002 · 登录限流与密码口径

2026-10-18，工程决策。API请求/响应不变；不会迁移现有密码散列或重置账号。实际运行结果见对应版本证据，不以本文件声明全项目安全验收通过。

当前密码为JDK实现的PBKDF2-HMAC-SHA256，每次独立随机盐、600000次迭代；早期验收计划中的“BCrypt”是未统一的草案措辞，现修正为实际选型。[OWASP密码存储指引](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)列出该PBKDF2工作因子，但使用此参数本身不意味着FIPS认证或整个应用已安全认证。

登录失败限流持久化在MySQL `fm_login_throttle`，以加域前缀后SHA-256为key，不存明文手机号或IP。账户与网络对端分别计数；所有检查/失败计数与登录事务提交，ApiException不会回滚失败计数。阈值配置启动时校验有界正整数。

| 默认项 | 环境变量 | 值 |
| --- | --- | --- |
| 账户失败阈值/窗口/封禁 | APP_LOGIN_ACCOUNT_MAX_FAILURES / APP_LOGIN_ACCOUNT_WINDOW_SECONDS / APP_LOGIN_ACCOUNT_BLOCK_SECONDS | 5次 / 60秒 / 900秒 |
| 连接对端失败阈值/窗口/封禁 | APP_LOGIN_IP_MAX_FAILURES / APP_LOGIN_IP_WINDOW_SECONDS / APP_LOGIN_IP_BLOCK_SECONDS | 50次 / 60秒 / 60秒 |

达到阈值的那次失败仍是通用401，随后请求429；Retry-After为实际剩余封禁秒数向上取整。封禁持续到截止时，不因计数窗口先过期提前解封。成功登录只清本人的账户失败数，不清共享IP失败数；不知道的账户与停用账户仍走通用失败，不暴露账号是否存在。

网络维度明确为Servlet原始连接对端，`server.forward-headers-strategy=none`；不相信客户端伪造的X-Forwarded-For或Forwarded。通过Vite/Nginx/平台代理时，多个访客可能共享同一对端；因此其阈值高于账户维度，正常成功登录不计入次数。此处不声称已识别真实访客IP。若以后需要可信代理链，必须针对真实平台验证并明确允许哪些上游，不能默认取用户可控头首项。

内部联系直接调用login(phone,password)保留账户维度，用于受控种子/测试；公开HTTP入口始终传入连接对端。当前并未把此策略泛化成注册、所有API、短信或支付统一限额，也不声称已接入泄露密码库检测、验证码或MFA。

同账户/同对端锁序一致，成功改密仍吊销会话；Redis故障不改变登录限流。原v0.2.1的账户5次/15分钟固定实现保留在历史提交，本版本按可配置策略推进。
