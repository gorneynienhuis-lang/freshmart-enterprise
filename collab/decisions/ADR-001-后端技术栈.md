# ADR-001 后端技术与部署基线

状态：Codex 决定，用于第一版实现；2026-10-18。补丁版本及依赖矩阵在首次可运行构建中锁定，当前不宣称已构建。

采用 Java 21、Spring Boot 4.1、Spring Security、MyBatis、MySQL 8.4 InnoDB、Flyway、Redis、Maven Wrapper、JUnit/Testcontainers。采用模块化单体，划分 identity、catalog、inventory、checkout、order、payment、fulfillment、aftersale、reporting、audit。Controller → Service → Mapper，Service 控制事务；跨模块通过明确应用服务调用，禁止 Controller 直接修改表。

开发端口：前端5173，后端8080，MySQL3306，Redis6379；生产只暴露反向代理入口，数据库/缓存/监控处于内网。前端Vite代理 `/api` 到8080；正式同源部署。必要的开发CORS仅允许明确列出的localhost来源，凭据不使用通配符。返回契约严格遵守 `contracts/conventions.md`。

库存、配送名额、优惠券、订单创建在一个MySQL事务里按固定锁顺序处理。库存及资金真相不放Redis；Redis用于限流和可丢弃缓存。使用数据库 outbox + 可重试任务处理超时关单、通知及退款；按唯一业务键确保幂等，不用Redis过期事件作为唯一关单机制。外部支付调用在本地事务之外，成功事实经幂等回调或主动对账入账。状态命令条件更新与 version 并用。

监控采用 Actuator + Micrometer，导出 Prometheus 指标；Grafana展示延迟/错误/库存冲突/支付回调和任务积压。traceId贯穿HTTP、日志、审计与事件。系统先以Docker Compose复现，再评估外部部署；不为课程验收引入微服务集群。

## 选型依据与被拒方案

- Spring Boot 3.5 原先最贴近队友建议，但官方已于2026-06-25说明3.5.16是该系列最后的开源支持版本，因此新项目改为4.1；保持Java21以减少不必要运行时升级。[官方3.5发布说明](https://spring.io/blog/2026/06/25/spring-boot-3-5-16-available-now/)
- 官方4.1.1文档允许Java17至26，Java21在支持范围内；实际依赖仍需首次构建核验，不能仅凭文档断言MyBatis/文档生成器兼容。[系统要求](https://docs.spring.io/spring-boot/system-requirements.html)
- 不整套引入RuoYi管理端：全部UI由Claude负责；现有角色、结果封装和状态语义需要按本项目契约实现。
- 不采用微服务/Kafka/Kubernetes作为起步条件：单库事务能覆盖当前核心一致性，复杂组件只在明确验收收益时增加。
- FEFO查询需要匹配索引与事务锁，普通快照读不能替代库存更新约束；并发验收必须针对真实MySQL。[InnoDB锁定读](https://dev.mysql.com/doc/refman/8.4/en/innodb-locking-reads.html)

风险：生态插件对Spring Boot4兼容必须验证；若必需依赖不兼容，先替换插件或手工托管OpenAPI，不静默退回停止开源支持的版本。运行生成的OpenAPI只作为漂移检测输入，人工维护契约仍为前后端协作来源，不能让生成文件自行覆盖已评审规则。
