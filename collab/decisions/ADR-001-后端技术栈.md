状态：第一批程序实现已构建并完成隔离测试；2026-10-18 更新。本文区分当前实现与后续目标。运行方法和实际接口范围见 [backend/README.md](../../backend/README.md)。

已锁定 Java 21、Spring Boot **4.1.1**、MyBatis Spring Boot Starter **4.0.0**、Maven Wrapper **3.3.4** / Maven **3.9.16**。运行时目标为 MySQL **8.4 InnoDB**，使用 JDBC/MyBatis 和 Flyway 版本化迁移。H2 仅为 test scope。采用模块化单体、Controller → Service → Mapper；Service 控制事务，数据库保存会话、商品、批次、幂等结果及审计。当前 HTTP 实现只有身份与公开商品的 **12 个合同操作**；纯领域类和数据库表不等同于订单/支付/履约接口已经接通。

## 当前鉴权实现与决策

当前使用自写的 `SecurityFilter extends OncePerRequestFilter`、`ApiAuthorizationRules` 显式方法/路由/角色注册，以及 `RequestActor`。**当前 pom 没有引入 Spring Security，不能称为 Spring Security 实装。** 原稿将 Spring Security 与 Redis/Testcontainers 并列写成已采用组件，现以本节的实现状态替代。

本阶段将会话、轮换、CSRF 和角色检查集中在少量可测试组件中，并用真实数据库事务验证关键路径。代价是过滤器顺序、错误处理、公开路由、跨域与新增接口授权的维护责任由项目承担；不能据此宣称生产安全验收完成。后续引入 Spring Security 时，应保留已评审的会话/权限契约并重新执行这些回归测试，不把框架依赖存在当作安全完成证据。

- API 路由按已评审合同显式列出。未注册 API 默认拒绝；公开商品 GET 与认证入口单独声明。角色每次从数据库读取，ADMIN 不继承 MEMBER 或其他业务角色。角色注册只确定操作入口，后续订单、售后和配送服务仍须逐资源检查所有者、门店、任务分派与状态。
- access JWT 使用 HS256，最长 900 秒；签名密钥来自 `APP_TOKEN_SECRET`，UTF-8 至少 32 字节，无内置默认密钥。access/refresh 的数据库持久化值均为 SHA-256 哈希，refresh 明文仅写 HttpOnly Cookie。
- refresh 每次轮换；旧凭据重放会吊销整个会话族。会话族绝对期限最多 7 天，轮换不延长期限，Cookie Max-Age 使用剩余时长。登录、刷新和改密统一先锁用户，再处理会话，改密吊销全部会话。
- Cookie 变更操作校验允许的精确 Origin、`csrf_context` Cookie 和 `X-CSRF-Token`；CSRF 上下文及 token 哈希存在数据库。Cookie 默认 Secure、HttpOnly、SameSite=Lax、Path=/api/v1/auth。只有本机 HTTP 联调可通过 `APP_SECURE_COOKIES=false` 关闭 Secure；部署使用 HTTPS。
- 密码使用 PBKDF2-HMAC-SHA256、每次独立随机盐和 600,000 次迭代。登录失败计数与限流状态使用数据库，不依赖 Redis。身份成功操作与刷新重放记录脱敏审计，不保存密码、token、Cookie 或完整手机号。
- 沙箱支付 callback 的路由预留跳过 Bearer；其渠道验签 handler **尚未实现**，当前不存在支付成功入口。后续实现必须独立完成 HMAC 验签、防重与金额核对。

## 运行与后续组件边界

开发端口为前端 5173、后端 8080、MySQL 3306；前端 Vite 的代理接线与正式同源反向代理仍按实际工程进度交付。CORS 只允许配置的精确来源，不使用凭据通配符。返回契约见 `contracts/conventions.md`。

Actuator、Micrometer 与 Prometheus registry 依赖已加入，health 可公开读取，其他已暴露监控端点受 ADMIN 检查；这不代表监控面板或告警已部署。Redis、Grafana、Docker Compose 完整复现环境、Testcontainers/MySQL 集成流水线仍待实现或执行。

后续库存、配送名额、优惠券与订单创建应在 MySQL 事务中按固定锁顺序处理；库存及资金真相不放 Redis。V002 已有 outbox 表，但重试 worker、超时关单和资金渠道适配器尚未接通。计划采用数据库 outbox 与唯一业务键，外部调用在本地事务之外，成功事实经幂等回调或主动对账入账。不得把表结构或纯领域规则测试写成这些流程已经运行。

## 已验证与未验证

第一批已真实通过 `IdentityIntegrationTest` 8 项和 `CatalogIntegrationTest` 5 项，包含 Flyway V001/V002、H2 MySQL 模式、MockMvc 过滤器与数据库事务。身份测试覆盖刷新重放、绝对期限、CSRF、角色拒绝、改密并发锁、限流及审计脱敏；商品测试覆盖上架过滤、临期/库存候选与分页排序。本轮随后全套 `clean package` 实际完成 60 项测试和 Spring Boot JAR 打包，见 [保存的报告与证据](../../docs/evidence/implementation-foundation/README.md)；这不等于应用已经启动部署。

**尚未进行真实 MySQL 8.4 启动、迁移、锁竞争、事务隔离与性能验收。** H2 通过只能证明对应隔离测试执行成功，不能替代这些验证。安全攻击面审查、订单资金闭环、真实后端 E2E 和生产部署均未完成。

## 选型依据与被拒方案

- Spring Boot 3.5 原先贴近队友建议，但官方说明 3.5.16 为该系列最后的开源支持版本，因此新项目采用 4.1；保持 Java 21。[官方发布说明](https://spring.io/blog/2026/06/25/spring-boot-3-5-16-available-now/)
- 当前 Boot 4.1.1 + MyBatis Starter 4.0.0 已在本项目编译及 H2 测试中通过；其他插件仍须逐项验证。[Spring Boot 系统要求](https://docs.spring.io/spring-boot/system-requirements.html)
- 不整套引入 RuoYi 管理端；UI 视觉由 Claude 负责，非视觉前端工程与后端由 Codex 实施，角色与状态语义遵守本项目合同。
- 不将微服务、Kafka 或 Kubernetes 设为起步条件；先完成单库核心一致性。
- FEFO 查询仍需真实索引与事务锁验证，普通快照读不能替代库存更新约束。[InnoDB 锁定读](https://dev.mysql.com/doc/refman/8.4/en/innodb-locking-reads.html)

人工维护的 OpenAPI 是协作契约。运行生成的描述只能作为漂移检测输入，不能自行覆盖已评审规则。后续新增操作必须同步权限注册与资源授权测试。
