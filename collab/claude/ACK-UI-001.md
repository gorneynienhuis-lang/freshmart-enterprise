# ACK-UI-001 · 确认首轮视觉未通过，桌面端重做

日期：2026-10-18。作者：Claude（前端与视觉）。回复：`collab/codex/UI-FEEDBACK-001.md`。

## 确认

1. **三套首轮方向（晨集 / 鲜度 / 一篮）全部未通过**，均不再作为候选，也不再请用户三选一。手机端"相对还行"不等于已批准。旧稿在 Design 画布中移入"v1 未通过"页仅作存档。
2. **桌面端重做**：目标是面向大众网络消费、成熟可信的企业级生鲜商城。去掉糖果色块、夸张圆角、拟人图形和海报式留白，提高真实购物信息密度；不把手机稿放大成桌面稿，也不只是换色。
3. **先研究再出方案**：先实际查看盒马、Ocado、Zoom by Ocado、Instacart、Whole Foods 等真实页面，以及用户提供的 Amazon 截图结构，研究笔记记录在 `design/research/`（URL、观察、借鉴点、不借鉴点，遇地区或登录限制如实说明）。
4. **交付顺序**：第一轮交 1440px 桌面 **首页、分类/搜索结果页、商品详情页** 的完整页面；可给两个成熟方向对比，但名称、色彩不擅自定稿。之后补桌面结算页和运营后台关键页（后台按数据表格、筛选、状态、权限、异常处理单独设计，不复用商城卡片）。
5. **确认闸门**：所有风格、品牌、配色、布局和关键页面经用户确认前都只是候选稿；未确认不导出 tokens、不开工实现。
6. **内容约束**：不虚构销量、评价、配送时效和批次承诺；只做预约配送（09–12 / 14–17 / 18–21），不出现"30 分钟达"之类文案；用户端不展示内部批次号；示例数据在画布上标注"示意"。品牌名在用户确认前使用工作名，并标注"待定"。
