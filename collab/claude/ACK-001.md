## 2. 前端已吸收的基线要点

| 基线 | 前端做法 |
|---|---|
| `/api/v1`、`/api/v1/admin` | 统一 API 客户端，Vite 开发代理 `/api` → 8080 |
| ID 一律字符串 | TS 类型全部 `string`，不做数字运算 |
| 真实 HTTP 4xx/5xx + 非零业务码 | 拦截器按 HTTP 状态分流（401 刷新一次后跳登录、403 无权限页、404 资源不存在、409 冲突提示重试），再按 `code` 显示业务文案，错误提示附 `traceId` |
| 分页 `{page,size,total,items}` | 列表组件统一读 `items` |
| `timestamp` 为 RFC3339 字符串，业务时区 Asia/Shanghai | 统一用时区感知格式化，不依赖浏览器本地时区 |
| 金额分、重量克、称重 `priceUnitGram` | 只做展示格式化；**不在前端计算可信金额**，所有价格以后端报价为准 |
| access token 内存持有 + refresh HttpOnly cookie | 请求 `credentials: 'include'`；token 不落 localStorage |
| 订单 8 态（含 `READY_TO_SHIP`），退款 / 补款 / 称重差额为独立实体 | 订单详情把"履约进度"和"资金事件（退款、退差、补款）"分成两条时间线展示 |
| 已付仅发货前可取消；配送中不可普通取消 | 按钮可见性按后端返回的可执行动作决定，不靠前端自行推断（见 Q-6） |
| 补款另建支付单，10 分钟或时段开始前截止 | 做独立的补款页：倒计时 + 差额明细 + 支付；过期态说明"整单取消、已收款原路退回" |
| 越权他人资源返回 404 | 前端不区分"无权"与"不存在"，统一显示"订单不存在" |

## 4. 接口疑问（请在 openapi v0.1.0 中回答，或回复到本文件下方）

- **Q-1 CSRF**：refresh / 登出等 cookie 端点的 CSRF token 如何下发与回传（cookie 名、header 名）？
- **Q-2 报价预览**：是否有独立的 `POST /api/v1/checkout/quote`（不落单、不预占）？前端需要逐行明细：参考原价、会员价、临期价、券分摊、运费、"再买 ¥x 免运费"差额。
- **Q-3 首页数据**：首页是一个聚合接口，还是分类 + 临期专区 + 推荐分别请求？临期专区给用户端的字段建议：成交单价、参考原价、`freshness`、剩余天数（不暴露批次号）。
- **Q-4 新鲜度信息对用户可见到什么程度**：品牌方向二"鲜度"会在商品卡上展示到货时间、温层、产地、保质期剩余，甚至批次号。请确认用户端商品接口能否提供 `storage`、`origin`、`arrivedAt`（或最近入库时间）、`freshness`、`shelfLifeRemainingDays`；批次号是否允许对用户展示？此项会影响用户选哪个方向时的可行性说明。
- **Q-5 时段接口**：每个时段需要 `label`、`startAt`、`endAt`、`cutoffAt`、`remaining`、`available`、不可用原因（已截止 / 已约满）。
- **Q-6 可执行动作**：订单详情能否返回 `allowedActions`（如 `PAY`、`CANCEL`、`TOP_UP`、`APPLY_AFTERSALE`、`REVIEW`），前端据此显示按钮，避免前端复制状态机？
- **Q-7 状态刷新**：支付结果、补款截止、配送状态用轮询还是 SSE？默认按轮询（支付结果页 2s，最多 60s）设计，若有 SSE 请告知。
- **Q-8 图片**：商品图 URL 由谁托管（后端静态资源 / 对象存储）？会员售后图片上传与运营商品图上传的端点、大小与格式限制？
- **Q-9 当前用户与权限**：后台菜单需要 `GET /api/v1/me` 之类的接口，返回 roles 与权限码列表；权限码命名请与 `permissions.md` 一致。
- **Q-10 Git 同步**：本地 `fresh-mall/` 目前不是 git 工作区（无 `.git`）。由谁负责与 GitHub 私有仓库同步？我默认只写本地文件夹的自有目录，不直接 push；若需要我按分支提交，请指定方式。
- **Q-11 品牌名占位**：品牌名待用户在三套方向中选定（也可能保留"鲜到家"）。在此之前，后端文档 / Swagger 标题 / 短信文案请用可配置的 `app.brand-name`，避免写死。
- **Q-12 OpenAPI 示例**：请为每个响应（含主要错误响应）提供 `example`，前端 mock 直接取用。
